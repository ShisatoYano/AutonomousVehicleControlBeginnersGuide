# CLAUDE.md

Guidelines for AI coding tools such as Claude Code when working on this project. Claude Code loads this file automatically.

## Project purpose

A collection of sample programs for learning autonomous driving algorithms (planned to be published as a technical book).
The top priority is making the algorithms easy to understand, not practicality or performance.
When considering an implementation, always put "is it easy to understand as learning material?" first.

## Language

This project is also for users outside Japan, so write everything that goes into the repository in English: code comments, docstrings, log/print messages, documentation (`*.md`), commit messages, and PR descriptions.
Conversations with the AI tool itself can be in any language.

## Documents to refer to

- `README.md`: Project overview, list of supported algorithms, setup steps
- `HOWTOCONTRIBUTE.md`: Flow for adding a new algorithm (Issue proposal → implementation → test → PR)
- `doc/DESIGN_DOCUMENT.md`: Design document of each program (work in progress)
- `doc/EXAMPLES.md`: Gallery of demo images. Generated by `generate_example_gallery.py` from the simulation scripts' docstrings and regenerated automatically by `.github/workflows/Update_Examples_Gallery.yml` after merge into main, so do not edit it by hand

## Directory structure

- `src/components/`: Reusable modules (vehicle, control, state, course, mapping, search, sensors, detection, obstacle, plan, array, visualization, common)
- `src/simulations/`: Scripts that run each algorithm, grouped by category (localization, mapping, path_planning, path_tracking, perception, course)
- `test/`: `test_*.py` for the simulations under `src/simulations` (almost 1:1)
- `doc/`: Design documents

## Coding conventions (patterns found in the existing code)

- Python only. The project doesn't use a standard package structure; each script loads modules under `src/components/` at runtime with `sys.path.append(...)` (follow the pattern of existing files)
- Put a docstring in the form `"""file name \n\n Author: <name>"""` at the top of each file
- In a simulation script under `src/simulations/`, the docstring must be exactly the file name, an empty line, and one line each of `Title:` (gallery heading), `Description:` and `Author:` in this order, following the template in `generate_example_gallery.py`. Don't write anything else in it. Scripts in the same directory must share the same `Title:`. The test fails otherwise
- In class and constructor docstrings, state the meaning and unit of each argument (naming convention puts the unit in the variable name, e.g. `f_len_m`, `max_accel_mps2`)
- Add type hints to the arguments and return values of new functions and methods, in simple forms (`list[float]`, `float | None`, `npt.NDArray[np.float64]`). Shapes of arrays go in the docstring, units in the names. Don't add type hints to unrelated existing code in the same change
- Simulation scripts have a `show_plot` flag and keep their logic in a `main()` function (so tests can set `show_plot = False` to stop the animation)
- After adding a new module directory (under `src/components/*` or `src/simulations/*`), run `python generate_pyrightconfig.py` on the host to regenerate `pyrightconfig.json` and `.devcontainer/devcontainer.json`

## Testing

- Run: `. run_test_suites.sh` (internally `pytest -l --durations=0`)
- When adding a new simulation, add a matching `test/test_<simulation_name>.py`. The basic pattern is a simple smoke test that sets `show_plot = False` and then calls `main()` (to check it runs without exceptions and without showing the animation)
- Also add the new simulation's folder to the "Sections" list of the book chapter it belongs to (`doc/<chapter>/index.md`). `test/test_book_chapters.py` fails if a simulation is in no chapter or in more than one

## Development flow

To add a new algorithm, follow Steps 1–4 of `HOWTOCONTRIBUTE.md` (Issue proposal → implementation → test → PR).

When creating a PR as the maintainer, assign it to `ShisatoYano` and add one type label (`bug`, `enhancement` or `documentation`) with `gh pr create --assignee ShisatoYano --label <label>`. Don't request a reviewer, since GitHub doesn't allow requesting the author.
